Festival Methodology - Core Principles
======================================

1. Goal-Oriented Development
----------------------------

Everything is organized around achieving a specific goal. A "festival"
represents the complete journey from problem to solution.

2. Requirements-Driven Implementation
-------------------------------------

CRITICAL: Implementation sequences can ONLY be created AFTER requirements
are defined. Never guess what to implement.

  Human provides:
  • Project goals and vision
  • Requirements and specifications
  • Architectural decisions
  • Feedback and iteration guidance

  AI agent creates:
  • Structured sequences from requirements
  • Detailed task specifications
  • Implementation code
  • Progress tracking and documentation

3. Phase Types
--------------

Every phase has a type that determines its structure. There are 6 types:

  planning         WORKFLOW.md with inputs/, decisions/, plan/ directories.
                   No numbered sequences or task files.

  implementation   Numbered sequences with numbered task files.
                   Quality gates appended from festival's gates/ directory.

  research         WORKFLOW.md with sources/, findings/ directories and
                   analysis templates. For investigation and exploration.

  ingest           WORKFLOW.md with input_specs/, output_specs/ directories.
                   For absorbing and processing external inputs.

  review           Freeform. PHASE_GOAL.md with review criteria and
                   stakeholder sign-off tables. No sequences or workflow.

  non_coding_action  Freeform. PHASE_GOAL.md with action items and
                     verification steps. No sequences or workflow.

Create a phase with a type:
  fest create phase --name "001_RESEARCH" --type research
  fest create phase --name "002_IMPLEMENT" --type implementation

4. Festival Types
-----------------

Festivals come in 4 types:

  standard           Full planning + implementation. Auto-scaffolds
                     INGEST and PLAN phases. Use this explicitly for
                     the beginner path.

  implementation      Execution-only. Auto-scaffolds IMPLEMENT phase.
                      Use when requirements are already defined, not as
                      the first-run default.

  research            Investigation-focused. Auto-scaffolds INGEST,
                      RESEARCH, and SYNTHESIZE phases.

  ritual              Recurring/repeatable. Custom structure from
                      ritual template. Stored in ritual/ directory.

Create a festival with a type:
  fest create festival --name "my-project" --type standard
  fest create festival --name "my-feature" --type implementation

Use 'fest types festival' to discover types.

5. Phase Structure Requirements
-------------------------------

Phase types enforce structural conventions used by the fest CLI's
agentic guidance system. fest validate checks compliance.

  Workflow phases:  planning, ingest, research use WORKFLOW.md
  Implementation:   MUST have numbered sequences with task files
  Freeform phases:  review, non_coding_action use only PHASE_GOAL.md
  Hybrid phases:    Can have BOTH workflow files AND sequences if needed

Common patterns:
  001_IMPLEMENT                              (requirements ready)
  001_RESEARCH → 002_IMPLEMENT               (investigate first)
  001_INGEST → 002_PLAN → 003_IMPLEMENT      (full planning)

6. Quality Gates
----------------

Every implementation sequence ends with quality gate task files defined in
the festival's gates/ directory, appended in sequential order. Default gates
are included (testing, review, iterate, fest_commit), but gates can be
configured per-festival based on that festival's specific needs.

Use 'fest gates apply --approve' to add gates to implementation sequences.

7. Step-Based Progress
----------------------

Think in steps, not time. Track progress by completed tasks, not hours.

8. Workflow Files and inputs/ Directories
-----------------------------------------

Planning, ingest, and research phases use WORKFLOW.md instead of sequences:

  WORKFLOW.md     Describes the planning process for a phase.
                  Placed directly inside the phase directory.

  inputs/         Holds reference materials, external documents,
                  and source content for planning.

  decisions/      Captures architectural and design decisions.

Example planning phase:
  001_PLAN/
  ├── WORKFLOW.md
  ├── inputs/
  │   └── requirements.md
  └── decisions/
      └── architecture.md

9. Campaign Context (Where Festivals Live)
------------------------------------------

fest operates on a `festivals/` workspace. That workspace commonly lives inside
a campaign: a git-native workspace AND memory layer (managed by `camp`) that
also holds projects, intents, and cross-festival context.

  campaign : workspace + memory   (projects, intents, context; managed by `camp`)
  festival : execution            (this methodology, running within the workspace)

fest also works standalone: `fest init` creates a bare `festivals/` workspace,
no campaign required. When a campaign is present, festivals gain its surrounding
workspace and durable memory; when it isn't, fest runs fine on its own.
