Task Files - Critical for AI Execution
======================================

THE CRITICAL DISTINCTION
------------------------

Goal documents define WHAT to achieve.
Task files define HOW to execute.

  SEQUENCE_GOAL.md  → Defines the objective
  01_design.md      → Task: specific work to perform
  02_implement.md   → Task: specific work to perform

AI agents EXECUTE TASK FILES, not goals.

Without task files, agents know the objective but don't know
what specific work to perform.


PHASE TYPES AND TASK CONVENTIONS
---------------------------------

There are 6 phase types, each with different structural conventions:

  IMPLEMENTATION phases - Numbered sequences + task files REQUIRED
    • Must have numbered sequence directories with numbered task files
    • AI agents execute structured task files autonomously
    • Quality gates appended from festival's gates/ directory
    • Sequences matching excluded_patterns in fest.yaml skip gates

  PLANNING phases - WORKFLOW.md (no sequences or task files)
    • Uses WORKFLOW.md for step-by-step planning process
    • Uses inputs/ directory for reference materials
    • Uses decisions/ directory for decision records
    • Uses plan/ directory for resulting plans
    • Do NOT create numbered sequences or task files

  RESEARCH phases - WORKFLOW.md (no sequences or task files)
    • Uses WORKFLOW.md for research process
    • Uses sources/ directory with INDEX.md for source tracking
    • Uses findings/ directory with INDEX.md for findings
    • Includes analysis templates (analysis.md, comparison.md, etc.)

  INGEST phases - WORKFLOW.md (no sequences or task files)
    • Uses WORKFLOW.md for ingestion process
    • Uses input_specs/ directory for raw input materials
    • Uses output_specs/ directory for structured output specs

  REVIEW phases - Freeform (no sequences, no workflow)
    • PHASE_GOAL.md defines review criteria and sign-off tables
    • Focus on validation and quality assurance
    • Simplest phase type

  NON_CODING_ACTION phases - Freeform (no sequences, no workflow)
    • PHASE_GOAL.md defines action items and verification steps
    • For documentation, process changes, non-code work

KEY RULES:
  • Implementation phases MUST have sequence directories and task files
  • Planning, research, and ingest phases use WORKFLOW.md (no sequences)
  • Review and non_coding_action phases are freeform (PHASE_GOAL.md only)

HYBRID PHASES:
  Some phases can have BOTH workflow files AND sequences.
  The workflow describes the process; sequences contain work items.


CORRECT IMPLEMENTATION STRUCTURE
---------------------------------

  02_api_endpoints/
  ├── SEQUENCE_GOAL.md          ← Defines objective
  ├── 01_design_endpoints.md    ← Task: design work
  ├── 02_implement_crud.md      ← Task: implementation
  ├── 03_add_validation.md      ← Task: more implementation
  ├── 04_testing.md             ← Quality gate
  ├── 05_review.md              ← Quality gate
  └── 06_iterate.md             ← Quality gate

CORRECT PLANNING STRUCTURE (also applies to ingest and research)
-----------------------------------------------------------------

  001_PLAN/
  ├── PHASE_GOAL.md             ← Phase objective
  ├── WORKFLOW.md               ← Step-by-step process
  ├── inputs/                   ← Reference materials
  │   └── requirements.md
  └── decisions/                ← Captured decisions
      └── architecture.md


INCORRECT STRUCTURE (Common Mistake)
------------------------------------

  02_api_endpoints/
  └── SEQUENCE_GOAL.md          ← WRONG: No task files!

  This tells agents WHAT to do but not HOW to execute.
  Agents need task files to work autonomously.


TASK FILE CONTENTS
------------------

Each task file should contain:

  # Task: [Name]

  ## Objective
  Clear statement of what this task accomplishes

  ## Requirements
  - Specific requirement 1
  - Specific requirement 2

  ## Implementation Steps
  1. First concrete step
  2. Second concrete step

  ## Definition of Done
  - [ ] Deliverable 1 complete
  - [ ] Tests pass
  - [ ] Documentation updated


QUALITY GATES
-------------

Quality gates are task files defined in the festival's gates/ directory,
appended to implementation sequences in sequential order:

  Default gates:
  • testing.md     - Testing and verification
  • review.md      - Code review
  • iterate.md     - Address review findings
  • fest_commit.md - Commit sequence changes

Gates can be configured per-festival by editing the gates/ directory
and fest.yaml. Sequences matching excluded_patterns in fest.yaml skip gates.
Use 'fest gates apply --approve' to add gates to implementation sequences.


PARALLEL EXECUTION
------------------

Nodes with the SAME number can run in parallel. This applies at every
level of the hierarchy — phases, sequences, and tasks:

  Tasks:     01_frontend.md + 01_backend.md (parallel within sequence)
  Sequences: 01_auth/ + 01_payments/ (parallel within phase)
  Phases:    002_FRONTEND/ + 002_BACKEND/ (parallel within festival)

  01_frontend_setup.md  ┐
  01_backend_setup.md   ├── Run simultaneously
  01_database_setup.md  ┘
  02_integration.md     ← Waits for all 01_ tasks

Sequential work is the default and normally preferred, but parallel
numbering enables independent work streams when appropriate.


CREATING TASK FILES
-------------------

Use the CLI to create task files efficiently:

  fest create task --name "design endpoints"
  fest create task --name "implement crud"
  fest create task --name "add validation"

Then add quality gates automatically:

  fest gates apply --approve


VALIDATE YOUR STRUCTURE
-----------------------

Run validation to check task files exist:

  fest validate tasks

This checks that implementation sequences have task files,
not just goal documents.

Full validation:

  fest validate

Post-completion checklist:

  fest validate checklist


COMMON MISTAKES
---------------

1. Creating only goal files
   WRONG: Only SEQUENCE_GOAL.md in implementation sequences
   FIX: Add task files (01_design.md, 02_implement.md, etc.)

2. Tasks too vague
   WRONG: "02_implement_feature.md" with no details
   FIX: Specific steps, requirements, and definition of done

3. Missing quality gates
   WRONG: Implementation tasks without testing/review
   FIX: Run 'fest gates apply --approve'

4. Sequences inside workflow phases
   WRONG: Numbered sequences in planning, ingest, or research phases
   FIX: Use WORKFLOW.md and the phase type's directory structure

5. Not filling templates
   WRONG: Task files with [FILL:] markers still present
   FIX: Replace all template markers with actual content


REMEMBER
--------

  Goals define WHAT to achieve.
  Tasks define HOW to execute.
  AI agents execute TASK FILES.

If your implementation sequences only have goals, agents won't know what to do.
If your workflow phases (planning, ingest, research) have sequences,
simplify to WORKFLOW.md and the phase type's directory structure.
