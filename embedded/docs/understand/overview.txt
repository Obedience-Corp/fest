Festival Methodology - AI Agent Build System
=============================================

Festival Methodology is a goal-oriented project management system designed
for human-AI collaboration and long-running autonomous development cycles.


CRITICAL: Tasks vs Goals (Most Common Mistake)
----------------------------------------------

  SEQUENCE_GOAL.md  → Defines the objective (WHAT)
  01_design.md      → Task file (HOW) ← AI executes THESE
  02_implement.md   → Task file (HOW) ← AI executes THESE

WITHOUT TASK FILES, AI knows the goal but not what work to do!

  WRONG: Sequence with only SEQUENCE_GOAL.md
  RIGHT: Sequence with SEQUENCE_GOAL.md + task files (01_*.md, 02_*.md, ...)

For details: fest understand tasks


Core Concepts
-------------

• Three-level hierarchy: Phases → Sequences → Tasks
• 6 phase types: planning, implementation, research, review, ingest, non_coding_action
• 4 festival types: standard, implementation, research, ritual
• Requirements-driven: Implementation only after requirements are defined
• Just-in-time context: Read templates and docs only when needed
• Quality gates: Every implementation sequence ends with testing, review, iteration


Festival Types
--------------

  standard              Full planning + implementation (use explicitly for
                        the beginner path)
  implementation        Execution-only (requirements already exist; not the
                        first-run default)
  research              Investigation and exploration
  ritual                Recurring/repeatable processes

  Discover types:  fest types festival
  Type details:    fest types festival show <type>
  Create:          fest create festival --name "<name>" --type <type>


Phase Types
-----------

  planning         WORKFLOW.md, inputs/, decisions/, plan/ (no sequences)
  implementation   Numbered sequences + numbered task files + quality gates
  research         WORKFLOW.md, sources/, findings/, analysis templates
  ingest           WORKFLOW.md, input_specs/, output_specs/
  review           Freeform (PHASE_GOAL.md with review criteria)
  non_coding_action  Freeform (PHASE_GOAL.md with action items)

  Create:  fest create phase --name "001_IMPLEMENT" --type implementation

Naming Conventions (MANDATORY)
------------------------------

  Phases:     NNN_PHASE_NAME      3-digit prefix, UPPERCASE (001_PLAN)
  Sequences:  NN_sequence_name    2-digit prefix, lowercase (01_requirements)
  Tasks:      NN_task_name.md     2-digit prefix, lowercase, .md extension


Quality Gates (REQUIRED for Implementation Sequences)
-----------------------------------------------------

Every implementation sequence MUST end with quality gate tasks:

  XX_testing.md      Verify functionality works
  XX_review.md       Review code quality
  XX_iterate.md      Address findings

Example: If your last implementation task is 03_*, quality gates are 04_, 05_, 06_


Token-Efficient Workflow
------------------------

Use the fest CLI instead of manual file creation:

  fest create festival --name "my-project" --type standard
  fest create phase --name "IMPLEMENT" --type implementation
  fest create sequence --name "api"
  fest gates apply --approve                 # Add quality gates

Variables are passed to templates - no post-creation editing needed.
